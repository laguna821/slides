# AS021 · 스크롤 중 목차와 테마 접근

사용자 요청: “웹 읽기 화면에서 스크롤링되도 다크 라이트 변경 버튼이 안밀리고 같이 나란히 목차랑 뜨게”. 사이트 정책을 3.2.0으로 올리고 기존 읽기 4건에 소급 적용했다.

## 구현과 등록 규칙

- 공통 `ThemeToggle`을 사이트 헤더, 읽기 고정 도구줄의 목차 옆, 목차 패널 제목 옆에 배치한다.
- 기존 `achmage-theme` 저장값과 모든 버튼의 다음 동작 레이블·상태를 함께 갱신한다. 전환 시 문서 내용이나 스크롤 위치를 재설정하지 않는다.
- 긴 목차 안에서도 제목과 전환 버튼을 고정한다. 44px 조작 영역과 기존 Enter/Space, Esc, 초점 복원을 유지한다.
- 빌드에서 도구줄·목차 패널의 버튼 누락을 검사한다. 배포 단계에서 모든 읽기의 `readerNavigation` 실측 기록을 요구한다. 누락·중복·가려짐·겹침·위치 이동·동기화 실패를 차단한다.

## 실제 검수

Windows Edge에서 빌드 출력으로 확인했다.

- 4개 읽기 × 375/768/1440px × light/dark = 24회. 처음·중간·끝 72개 위치에서 버튼 가시성, 같은 줄 배치, 겹침 없음, 44px 영역을 확인했다.
- 실제 테마 클릭 전후 스크롤 차이는 0px였다. 모든 버튼의 상태 동기화, 목차 안 전환, 설정의 새로고침 유지, Enter 전환, Shift+Tab 탐색, Esc 닫기와 초점 복원을 확인했다.
- 35개 생성 경로의 210개 화면에서 가로 넘침·깨진 이미지가 없었다.
- 320×640 및 768×375에서 읽기 4건을 추가 확인했다. CSS 2배 확대 fixture에서도 같은 줄·가시성·겹침 검사를 통과했다. 이는 운영체제 확대나 브라우저 네이티브 줌 인증을 의미하지 않는다.
- 각 읽기의 본문·Markdown 복사, 실제 Markdown 다운로드, 연결 지도, 이미지 확대를 다시 확인했다. 이미지가 없는 AI 읽기 파일럿은 확대가 해당 없음이다.
- PDF 링크를 확인했고, 원문·이미지·PDF·인쇄 입력은 변경하지 않았다. 기존 AS020의 같은 바이트에 대한 PDF 검증을 재사용한다. 네이티브 PDF 뷰어·실물 인쇄·스크린리더를 이번 변경에서 새로 검증했다고 주장하지 않는다.

검사 도구는 sticky 요소를 조작하기 전에 페이지를 자동으로 중앙 정렬했다. 이를 제품의 테마 전환으로 오판하지 않도록 로컬 측정 서버에서 실제 click 직전과 두 프레임 뒤 scrollY를 기록했다. 측정 스크립트는 화면·동작을 변경하지 않으며 운영 출력에 포함하지 않는다. 새로고침 직후 Space 입력의 자동 검사 결과는 간헐적이어서 Space는 별도로 확인하고 반복 행렬은 Enter/Esc 기준으로 기록했다.

`validation/release-review.json`에 실제 결과와 전체 파일 해시를 연결한다. 재검토하지 않은 이전 동작은 재사용 근거를 명시한다. GitHub main 보호 설정은 사용자의 보류 지시를 유지한다.
