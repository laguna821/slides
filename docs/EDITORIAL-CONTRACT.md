# 웹 편집본 계약 2.0 · 사이트 정책 4.0

원문 보관과 독자용 편집을 분리한다. 기존 HTML·Markdown·PDF는 바꾸지 않는다. 발표 번호·반복 푸터·장식 문구는 편집본에서 정리하되 주장, 수치, 직접 인용, 부정·조건·한계와 출처는 보존한다. 원문에 포함된 주장은 새로운 사실 검증 결과로 표현하지 않는다.

## 등록

1. 원문 reader.source와 보존 manifest를 고정한다. 원문 텍스트·이미지 검사를 먼저 통과한다.
2. content/editorial에 별도의 Markdown 원고를 작성한다. 슬라이드를 논지별 H2로 묶고 H3 이하로 전개한다. 제목은 문장으로 읽히게 다듬고 번호·강제 줄바꿈·단순 반복을 편집한다.
3. 원문 단위마다 unit 주석과 대응표를 작성한다. 원문·편집본 해시, 기존 heading ID, 편집 이유, 검토 상태를 기록한다. 의미 보존은 문자열 유사도로 승인하지 않고 원문과 대조한다.
4. 도해의 OCR 문장 나열은 문단·목록·표로 편집한다. 원본 이미지는 모두 유지한다. 긴 alt에만 핵심 내용을 숨기지 않는다.
5. 링크 문법을 AST/DOM의 텍스트 노드에서 검사한다. 코드 예시는 제외한다. 내부 파일과 fragment를 검사하고 숫자 slide hash는 등록된 엔진 동작으로 확인한다.
6. 외부 링크는 응답과 리다이렉트를 기록한다. 404/410은 수정하거나 서지 정보를 남긴 비링크로 전환한다. 403·429·인증·시간 초과는 만료로 단정하지 않고 검토 이유를 기록한다. 링크를 임의의 다른 자료로 대체하지 않는다.
7. 검토 후 manifest status를 reviewed로 고정한다. 원고·대응표가 변경되면 검토를 갱신한다. 링크 영수증도 원고 해시에 묶는다.

## 공통 출력

웹·목차·검색·본문 복사·read.md·read.txt·HanMark PDF는 동일한 편집본에서 생성한다. source.md는 원문 보관본으로 명확히 구분하고 noindex로 제공한다. 기존 fragment는 편집본의 해당 원문 단위로 연결한다. H4 이하 세부 항목은 본문에 남기되 목차에는 H2/H3만 표시한다.

## 화면

Pretendard와 Major Second 1.125 배율을 사용한다. 본문 17–18px, 행간 1.8. H1/H2/H3/H4는 본문의 약 2.0273/1.6018/1.2656/1.125배다. H2에는 브랜드 블루 선과 짧은 틸 시작점을 둔다. 본문 폭은 데스크톱 약720px, 모바일 여백18px를 기준으로 한다.

목차와 테마 버튼은 스크롤 중 같은 도구줄에 남는다. 상시 # 표시는 금지한다. 데스크톱 문단 링크는 hover/focus에 표시하고 모바일에서는 읽기 도구의 현재 문단 링크 복사를 제공한다. 본문·목록·표·인용·캡션을 서로 구별하며 모두 카드로 만들지 않는다.

## 출시

기존 4편을 포함한 전체 읽기와 설명 영역에 소급 적용한다. original coverage, editorial map, image coverage, link receipts, PDF input digest를 모두 검사한다. 375/768/1440px 양 테마와 320px 좁은 화면·1920px 큰 화면, 긴 표·제목·링크·이미지 확대·키보드·고정 탐색을 검수한다. 기존 release:verify를 우회하지 않는다.
