# 공용 폰트 이전 검증 기록

기준: main cee81c0, 정책 6.5.0 → 6.6.0. R-006 근거는 `research:rr-34960557942b56ef5bc205fefd4b3eec:103a136dd5141458b95d11ed65825d7e691a15f117f7c88c9f93af9fbf39d822`이다.

폰트 8개의 원본 합계는 8,205,060바이트다. SameTone Full 1.000과 100–900 가변 굵기, 기존 발표 원본과 노트는 유지한다.

## 실행 중 발견 및 보정

- 관리 실행기의 workspace를 저장소 부모로 지정한 첫 npm ci는 package-lock을 찾지 못했다. 실제 slides 디렉터리로 수정한 두 번째 실행은 성공했다.
- 자동 Research Register 저장은 로컬 64MiB 한도로 거부되었다. 기존 기록을 삭제하지 않고 이 파일에 실행 근거를 보존한다.
- 2026-11-02 첫 대시보드 배포(9ce98b30): 폰트 SHA는 맞으나 MIME은 application/octet-stream이었다. 긴 로컬 경로의 일부 TXT는 0바이트로 업로드되었다. 공개 HTTP로 확인했다. 아직 사용 코드/클로드 안내를 제공하지 않았다.
- 다음 실험: 각 폰트 경로의 Content-Type을 _headers에 명시하고, 동일 바이트의 정적 묶음을 짧은 작업 경로로 복사해 업로드한다. 서버의 SHA·크기·MIME·CORS·캐시를 다시 검사한다. 길이 문제가 원인이라는 해석은 검증 전 가설이다.
- 수정 배포 0503b07c: 짧은 경로에서는 라이선스 네 개가 실제 크기로 전송되었다. `fonts:verify`가 폰트 8개, CSS 2개, 라이선스·NOTICE 4개 총 14개의 공개 SHA256·크기·MIME·CORS·캐시를 통과했다. 직접 메시지 API가 없는 Claude 기존 세션에는 아직 전송하지 않았으며 전달문을 제공했다.
- 새 체크아웃에서 첫 content:check는 아직 생성되지 않은 legacy public 사본 때문에 실패했다. build:source 준비를 먼저 실행하니 보관 원본·노트·한영 68쌍 검사가 통과했다.
- 테스트 1회는 Pele 폰트 proxy를 redirect로 바꾼 후 vercel.json 재생성 전 실행되어 실패했다. web:prepare로 정식 redirect/rewrite 산출물을 갱신한 후 같은 검사를 다시 실행한다.

## 게시 계약

폰트 공용 서비스를 먼저 검증한다. 사이트 운영 반영은 현재 digest와 실제 화면 검토가 완성된 후 UPLOAD-CONTRACT의 사용자 확인을 따른다.

## 확인 결과

- 공개 서비스: `https://achmage-fonts.laguna821-c08.workers.dev`. 실행 코드 없이 Static Assets만 배포했다. 이전 14개 주소를 보존하는 검사를 이후 준비·배포에도 적용한다.
- 원본 폰트 8개의 SHA256과 크기를 유지했다. 실제 Edge에서 원본과 공용 파일의 한글·영문 줄바꿈을 비교했으며 100/400/700/900 가변 굵기도 일치했다. 좌표의 부동소수점 차이는 최대 0.000061px이었다. 초기 검사 코드의 완전 일치 비교를 0.05px 허용 비교로 수정했으며 폰트 자체는 변경하지 않았다.
- 동일 사이트 내 재요청에서 8개 모두 transferSize 0의 캐시 재사용을 확인했다. 다른 사이트 간 캐시 공유나 첫 방문 속도 향상을 보장하지 않는다. 최초 폰트 다운로드 바이트는 그대로다.
- 전체 공개 경로 184개의 375/768/1440px, light/dark 조합 1,104개를 실제 Edge iframe에서 측정했다. 가로 넘침과 깨진 이미지가 없었다. 개별 프레젠테이션 엔진의 테마 지원 방식은 원래대로 유지했다. 자동 측정 전체를 사람이 하나씩 시각 검토했다고 주장하지 않는다.
- Pele의 style.css와 app.mjs는 보관 원본을 유지하고 web-dist의 파생본만 직접 공용 폰트 주소로 연결했다. 그 외 R2 이미지와 엔진 자산은 기존 구성을 유지한다. 최종 설정의 Pele 46개 경로·276개 조합을 다시 측정했고 공용 URL 직접 요청, 중복 요청 0개, 화면 오류 0개를 확인했다.
- 한국어·영어 HTML/CSS 복사 버튼을 실제 브라우저에서 확인했다. 기존 검색·읽기·포스터 기능 증거는 원래 검토 시각을 유지하고, 관련 소스 및 원본 폰트가 그대로임을 해시로 확인해 이어받는다. 새 폰트 검증과 전체 화면 측정은 이번 결과로 별도 기록한다.
- 배포 폴더는 기존 25,151,377바이트에서 17,010,233바이트(16.22MiB)로 줄었다. 절감량은 8,141,144바이트, 32.37%다. 폰트 바이너리는 web-dist에 없고 원본 저장소와 이력에는 보존한다.
- 타입 검사 오류 0개, 테스트 103개 통과, storage:check 통과. 공개 폰트 검증 영수증은 validation/font-cdn-verification.json에 보존한다.
