# 콘텐츠 등록과 AI 관리

## 공통 데이터

`content/works.json`은 자료, `media.json`은 영상과 버전, `usages.json`은 발표에서 영상 구간을 사용한 관계입니다. 스키마는 `src/lib/schema.ts`가 단일 기준입니다. 화면의 카드·개수·검색·관련 자료는 이 데이터로 생성합니다.

자료의 `id`는 변경하지 않습니다. `slug`를 바꿀 때는 이전 URL에 리다이렉트를 추가합니다. `kind`는 talk/lecture/motion/note, `status`는 selected/study입니다. 대표작 선정은 사용자 평가 기록에 근거하며 `featuredOrder`로 홈의 순서를 명시합니다. 모든 날짜는 YYYY-MM-DD입니다. 기존 모션 날짜는 제작일을 추정한 값이 아니라 아카이브 등록일입니다.

`course.id`는 한 과목·한 학기를 식별합니다(예: ai-design-2026-1). 같은 ID로 서로 다른 과목명이나 학기를 등록하면 빌드가 실패합니다. 주차는 `course.week`에 넣습니다. 강의가 등록되면 과목 페이지가 자동 생성됩니다.

`artifacts`에는 실제 제공하는 HTML/Markdown/PDF/link만 넣고, `modes`에 present/read/download를 선언합니다. PDF가 없으면 PDF 버튼을 만들지 않습니다. 기존 독립 HTML은 직접 연결하며 자동 개조하지 않습니다. 생성 읽기 화면은 원본 발표 캔버스와 별개로 전체 원문을 읽는 화면입니다. 요약으로 대체하지 않습니다. 신규 등록과 기존 이관은 docs/READER-CONTRACT.md의 reader 원고·출처·대응표·검사 절차를 적용합니다. 아래의 이전 htmlSource/markdownSource 직접 읽기 등록은 신규 자료에 사용하지 않습니다.

## 공개 정책

| visibility / seo   | 결과                                                    |
| ------------------ | ------------------------------------------------------- |
| listed / index     | 목록·검색·사이트맵에 포함, 검색엔진 노출 허용           |
| listed / noindex   | 목록·검색 포함, 상세·읽기 페이지 noindex, 사이트맵 제외 |
| unlisted / noindex | 링크로 열 수 있음, 목록·검색·사이트맵 제외              |
| draft              | 생성 페이지·검색·관계 데이터에서 제외                   |

`noindex`와 unlisted는 접근 통제가 아닙니다. 실제 비공개 자료는 업로드하지 않습니다. **GitHub 저장소와 `public/` 안의 파일은 별도 공개 표면**이므로 draft 원본을 여기에 놓아서는 안 됩니다. 자동 검사도 사람의 공개 승인을 대체하지 않습니다. 공개 자료가 unlisted/draft 소유의 영상이나 자막을 참조하면 관계 검증이 차단합니다.

암호화 발표자 노트는 승인된 엔진이 만든 암호문 형식을 그대로 연결합니다. 사이트는 비밀번호를 받거나 암호화를 새로 구현하지 않습니다. 공개 원본·PDF·검색 색인·검토 데이터에서 노트 평문 및 비밀번호가 없는지 확인합니다. HTML 추출은 script를 실행하지 않으며 hidden/script/노트 영역과 발표 도구 UI를 제거합니다. 새로운 엔진의 노트 속성이 추가되면 추출 제외 규칙과 누출 테스트도 갱신해야 합니다.

기존 파일 예외: AI_reading_3week_pilot_20261008.html은 이 작업 이전부터 평문 노트를 포함해 공개되어 있었다. URL과 바이트 보존을 우선해 유지했으며 새 색인/읽기에서 노트를 제외한다. 새 자료에는 이 예외를 적용하지 않는다. 원본 암호화는 엔진으로 다시 생성하는 별도 변경이다.

## HTML과 Markdown 등록

1. AI에게 공개할 정확한 파일, 제목, 분류, 공개 정책, 대표작 여부를 전달합니다. 명시되지 않은 주변 폴더는 등록하지 않습니다.
2. HTML은 아래 명령으로 **로컬 검토 후보**를 생성합니다. 같은 ID를 덮어쓰지 않습니다.

```sh
npm run content:import -- --file "발표.html" --id "talk-id" --title "공개 제목" --date 2026-10-08
```

3. `.local/imports/<id>/candidate.json`의 노트·영상·출처를 확인합니다. 검토용 필드(sourceSha256/extractedVideos/review)는 공개 스키마에 복사하지 않습니다.
4. 승인된 공개 HTML과 그 자산만 `public/decks/<id>/`에 옮기고 works에 `htmlSource`, HTML artifact를 등록합니다. Markdown은 공개 가능한 원문만 `content/sources/`에 두고 `markdownSource`를 지정합니다. 상대 이미지·링크는 실제 배포 경로에서 검사합니다.
5. 포스터 WebP, PDF(실제 있을 때), 자막(실제 있을 때)을 등록합니다. 이미지 alt를 작성합니다.
6. `npm run content:check` → 테스트 → 타입 검사 → 빌드 → 로컬 화면 → Vercel 미리보기를 검증합니다.
7. 검증한 변경을 `main`에 반영하고 실제 운영 주소에서 자료와 기존 발표를 다시 확인합니다.

HTML의 video/source/iframe/링크는 `.local/media-candidates.json`에 정규화 후보로만 추출됩니다. YouTube 중복 링크는 영상 ID 기준으로 합칩니다. 외부 링크는 원본 보기로 연결합니다. 추출 후보가 수동 설명·버전·구간을 덮어쓰지 않습니다.

## 영상과 사용 관계

한 작품은 카드 하나를 유지하고 `media.versions`에 출력 버전을 추가합니다. 기존 버전을 삭제·교체하지 않고 `currentVersion`만 선택합니다. 과거 발표의 `usages.version`은 변경하지 않습니다. MP4는 확인된 공개 주소를 참조하며 이 저장소에 복제하지 않습니다. 현재 공개본은 Achmage-Skills의 커밋 SHA에 고정되어 있습니다.

모션 페이지에서 시작/끝(초)을 지정하면 구간 링크, iframe, AI용 JSON을 복사할 수 있습니다. 버전 ID와 구간이 URL에 들어갑니다. iframe은 자동 재생하지 않고 사용자가 재생하며 기본 음소거입니다. JSON을 관계 데이터에 사용할 때는 `workId`, `slideId`(있을 때), `label`, `role`을 채워 아래 스키마대로 등록합니다.

```json
{
  "workId": "talk-id",
  "mediaId": "water-film",
  "version": "water",
  "slideId": "s03",
  "start": 1,
  "end": 3,
  "role": "explanation",
  "label": "흐름을 설명하는 장면"
}
```

실제로 쓰이지 않은 과거 발표 관계는 만들어 넣지 않습니다. 자막은 해당 버전의 `captions`에 WebVTT 경로로 연결하면 본문 검색에도 포함됩니다. 원본 영상 장애 시 직접 링크를 보여줍니다. 원본 서버도 장애라면 같은 링크로 복구되지는 않으므로 주소를 점검해야 합니다.

영상 검색/개수는 동일 데이터를 사용합니다. PDF의 영상은 포스터+링크로 제공하며, 영상 파일을 포함하지 않은 문서를 완전한 오프라인 자료라고 표시하지 않습니다. 영상 포함 ZIP은 실제 묶음 파일이 만들어지고 검증된 경우에만 artifact로 등록합니다.

## AI에게 전달할 운영 요청 예

“이 HTML을 강의/2026-1/3주차로 등록해 줘. 목록 공개, 상세 noindex, 대표작 아님. 원본을 보존하고 노트 노출 검사와 검색·영상 연결을 검증한 뒤 Vercel 미리보기를 확인해서 main에 반영해 줘.”

AI는 기존 사용자 선정과 공개 정책을 보존합니다. 공개 상태나 대표작 여부가 불명확하면 로컬 후보 상태로 두고 필요한 정보만 확인합니다. 검증 로그와 배포 커밋을 작업 기록에 남깁니다.

## 읽기 화면 고정 탐색 (사이트 정책 3.2.0)

읽기 화면 변경 시 정책3.2.0의 고정 탐색 검사를 함께 실행한다. 각375/768/1440px·양테마에서 처음/중간/끝 목차·테마의 가시성/정렬/겹침과44px조작영역,전환 시 위치 유지·동기화·새로고침 후 테마 보존·키보드를 실제 측정하여 readerNavigation을 갱신한다.

구현·검증 근거는 [AS021](AS021-READER-NAVIGATION.md)에 기록한다. 새 읽기도 공통 컴포넌트를 사용하고 같은 검사 행렬에 자동 포함한다.

## 읽기용 PDF (사이트 정책 3.1.0)

[HanMark 읽기용 PDF 계약](PRINT-CONTRACT.md)을 적용한다. 모든 공개 읽기에 첫 쪽 제목·본문 통합 A4 2단 PDF가 필수다. `npm run print:generate`로 생성하고 원문·자산·조판 입력 해시와 실제 PDF 검증을 통과해야 게시할 수 있다. 변경 시 기존 읽기 전체에 소급 적용하며 발표 PDF·A2 포스터는 별도로 보존한다.
