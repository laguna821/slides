# 발표자 노트 · 사이트 정책 5.2

최근 Achmage Presentation HTML은 N 키와 노트 버튼으로 암호 입력 화면을 열어야 한다. 사이트 기본 암호는 사용자가 별도로 지정한 로컬 프로필 `studio-presenter-default-v1`을 사용한다. 실제 값은 공개 저장소·HTML·PDF·검색 데이터·검증 영수증에 기록하지 않는다.

## 생성

- 기존 엔진/덱 핀과 원본 URL은 보존한다. 사이트 전용 `scripts/package-notes.py`는 승인된 HTML의 단일 `speaker-notes-enc` 데이터만 교체하며 렌더러나 브라우저 코드는 변경하지 않는다.
- producer1.0.0은 고정 엔진369538c1의 PBKDF2-SHA256 600,000회/AES-256-GCM 형식에 호환된다. 사용자 지시에 따른 이 사이트의 숫자 네 자리 예외를 지원한다. 공용 OS 엔진의 암호 정책을 변경한 것이 아니다.
- 암호는 숨김 프롬프트로 전달한다. 명령행 인자·환경변수·로그에 넣지 않는다. 원본 노트 JSON은 저장소 밖에 보관한다.
- 노트가 없으면 명시적 `--empty`로 잠금만 설정한다. `notesState: empty`를 기록하고 노트 작성/복원 완료라고 표현하지 않는다. 민감한 비밀을 강하게 보호하는 수단으로 네 자리 잠금을 홍보하지 않는다.
- 새로운 경로로 출력한다. 한영 소개는 같은 공개 발표 파일을 참조하며 원본 슬라이드 언어는 유지한다. PDF와 기존 읽기 자료는 변경하지 않는다.

## 등록과 차단 검사

`content/presenter-notes.json`에 원본·출력 SHA256, 실제 노트 유무, 기존 엔진과 별도 producer를 기록한다. 모든 공개 HTML 슬라이드는 등록 대상이다. 원본 보존 예외는 현재의 구형 세 작품과 정확한 해시만 허용한다. 신규 작품을 예외에 자동 추가하지 않는다.

`prepare.ts`는 누락·암호화 형식·원본 외 변경·producer 변경·검수 영수증 누락을 차단한다. 형식 검사만으로 지정한 암호를 확인했다고 주장하지 않는다. 새 산출물마다 실제 기본 암호로 열어 보고 잘못된 암호 거부, N 입력창, 재잠금, 새로고침 후 잠금을 정확한 HTML 해시에 연결해 기록한다. 팝업 차단 시 내장 노트 패널도 점검하고 미검증 조건을 숨기지 않는다.

공개 영수증은 암호를 담지 않는 검증 결과이며 외부 보안 서명이 아니다. 사용자 기본값은 프로젝트 메모리에서 회수하되 웹에 노출하지 않는다.

## 확인된 봉투의 이월 · 2026-11-02

소유자가 PC에서 암호를 입력할 수 없을 때 수정판은 실제 암호로 확인된 직전 산출물의 덱 ID를 유지하고 그 암호화 봉투를 바이트 그대로 옮길 수 있다(`.local/carry-notes-envelope.py`). 이때 N 입력창·잘못된 암호 거부·새로고침 잠금·새 탭·팝업 차단 시 내장 패널은 새 파일에서 직접 확인한다. 암호 해제와 재잠금은 봉투·덱 ID(AAD)·노트 런타임이 바이트 단위로 같을 때만 직전 확인을 이어받으며, 영수증에 `inheritedFrom`과 `inheritedChecks`로 이어받았음을 밝힌다. 소유자가 PC를 쓸 수 있게 되면 실제 암호로 다시 확인한다.

## 잠금 대기 · 2026-11-16

소유자가 원격이라 암호를 입력할 수 없고 노트가 **비어 있는 새 덱**은 잠금 없이 먼저 게시할 수 있다(소유자 결정: “원격이라 pin을 넣을수가 없는데 어떻하지” → “잠금 없이 먼저 게시”, 2026-11-16). `content/presenter-notes.json`의 `pendingLock`에 등록하며, 조건은 다음과 같다(`scripts/notes-contract.ts`가 하나라도 어긋나면 빌드를 막는다).

- 공개 파일(index.html)이 승인된 사이트 원본(source.html)과 바이트까지 같다. 엔진 출력에 아무것도 더하지 않는다.
- 노트 데이터(`speaker-notes-enc`)가 정확히 `null`이다. 작성된 노트가 있는 덱은 해당하지 않는다.
- 엔진 출처(provenance)가 승인된 것이고, `notesState`는 `none`이다.
- 소유자 결정의 원문·세션·시각이 기록돼 있다. 같은 덱이 `decks`(잠금 완료)와 동시에 오를 수 없다.

이 상태에서도 N 키는 엔진 그대로 노트 창(`?view=notes`)을 열고, 창에는 ‘포함된 노트 없음’과 엔진의 암호 입력란이 보인다(풀 노트가 없으므로 어떤 값으로도 열 내용이 없다, `.local/pending-notes-check-11w1.json`). 노트를 제공하거나 잠갔다고 소개하지 않는다. 소유자가 PC를 쓸 수 있게 되면 index.html 사본과 `pendingLock` 항목을 지우고 일반 잠금 절차(숨김 입력 + 브라우저 확인)로 같은 주소에 잠금판을 올린다.

## 소유자 기기 잠금 · 2026-11-16

소유자가 원격이라 PC의 숨김 입력을 쓸 수 없으면, 소유자 계정만 열고 읽고 쓸 수 있는 비공개 claude.ai 페이지에서 PIN을 받아 잠글 수 있다(소유자 요청: “그냥 여기 모바일 채팅창에다가 너는 볼수없고 나만 입력하는 팝업창 띄우면 되잖아”, 2026-11-16). 11W-1이 첫 사례로, 잠금 대기 대신 이 방법으로 잠갔다.

- 페이지는 PIN을 그 기기 안에서만 쓴다. 노트(빈 덱이면 `{}`)를 producer와 같은 형식과 직렬화(PBKDF2-SHA256 600,000회, AES-256-GCM, 덱 ID AAD)로 봉투에 담는다. 그다음 덱에 들어 있는 노트 런타임을 그대로 실행해 틀린 값 거부, PIN 해제, 다시 잠그기를 확인한다(HTML 줄바꿈 정규화 뒤 SHA-256이 같아야 한다). 저장하는 것은 봉투와 확인 결과뿐이며, PIN은 저장하거나 보내지 않는다.
- `.local/apply-owner-envelope-11w1.ts`가 저장된 결과를 덱과 대조한다(덱 ID, 런타임 해시, 다섯 확인, 직렬화). 그 뒤 단일 `speaker-notes-enc` 데이터만 바꾸며, 노트 외 바이트는 원본과 같다.
- N 입력창, 잘못된 암호 거부, 새로고침 잠금, 새 탭, 팝업 차단 시 내장 패널은 새 파일에서 PIN 없이 직접 확인한다. 해제와 재잠금은 봉투, 덱 ID(AAD), 노트 런타임이 바이트 단위로 같을 때만 소유자 기기 확인을 쓴다. 영수증에는 이를 `ownerDevice`와 `ownerDeviceChecks`로 밝힌다(확인된 봉투의 이월과 같은 원리). 이 파일의 노트 창 안에서 PIN으로 다시 열어 본 것은 아니라는 점도 함께 적는다.

게시 확인은 docs/UPLOAD-CONTRACT.md의 상시 게시 위임을 따른다.
