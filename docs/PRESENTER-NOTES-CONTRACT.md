# 발표자 노트 · 사이트 정책 5.2

최근 Achmage Presentation HTML은 N 키와 노트 버튼으로 암호 입력 화면을 열어야 한다. 사이트 기본 암호는 사용자가 별도로 지정한 로컬 프로필 `studio-presenter-default-v1`을 사용한다. 실제 값은 공개 저장소·HTML·PDF·검색 데이터·검증 영수증에 기록하지 않는다.

## 생성

- 기존 엔진/덱 핀과 원본 URL은 보존한다. 사이트 전용 `scripts/package-notes.py`는 승인된 HTML의 단일 `speaker-notes-enc` 데이터만 교체하며 렌더러나 브라우저 코드는 변경하지 않는다.
- producer1.0.0은 고정 엔진369538c1의 PBKDF2-SHA256 600,000회/AES-256-GCM 형식에 호환된다. 사용자 지시에 따른 이 사이트의 숫자 네 자리 예외를 지원한다. 공용 OS 엔진의 암호 정책을 변경한 것이 아니다.
- 암호는 숨김 프롬프트로 전달한다. 명령행 인자·환경변수·로그에 넣지 않는다. 원본 노트 JSON은 저장소 밖에 보관한다.
- 노트가 없으면 명시적 `--empty`로 잠금만 설정한다. `notesState: empty`를 기록하고 노트 작성/복원 완료라고 표현하지 않는다. 민감한 비밀을 강하게 보호하는 수단으로 네 자리 잠금을 홍보하지 않는다.
- 새로운 경로로 출력한다. 한영 소개는 같은 공개 발표 파일을 참조하며 원본 슬라이드 언어는 유지한다. PDF와 기존 읽기 자료는 변경하지 않는다.

## 등록과 차단 검사

`content/presenter-notes.json`에 원본·출력 SHA256, 실제 노트 유무, 기존 엔진과 별도 producer를 기록한다. 모든 공개 HTML 슬라이드는 등록 대상이다. 원본 보존 예외는 현재의 구형 세 작품과 정확한 해시만 허용한다. 신규 작품을 예외에 자동 추가하지 않는다.

`prepare.ts`는 누락·암호화 형식·원본 외 변경·producer 변경·검수 영수증 누락을 차단한다. 형식 검사만으로 지정한 암호를 확인했다고 주장하지 않는다. 새 산출물마다 실제 기본 암호로 열어 보고 잘못된 암호 거부, N 입력창, 재잠금, 새로고침 후 잠금을 정확한 HTML 해시에 연결해 기록한다. 팝업 차단 시 내장 노트 패널도 점검하고 미검증 조건을 숨기지 않는다.

공개 영수증은 암호를 담지 않는 검증 결과이며 외부 보안 서명이 아니다. 사용자 기본값은 프로젝트 메모리에서 회수하되 웹에 노출하지 않는다.

정책5.1의 구체적 결과 확인 후 게시 절차는 그대로 적용한다.
