# 읽기용 PDF 계약 1.0.0

사이트 정책 3.1.0부터 모든 공개 읽기에 HanMark 기반 PDF를 함께 제공한다. 웹 읽기와 같은 공개 원문·이미지가 유일한 본문 출처이며, 발표 슬라이드 PDF 및 A2 포스터와 별도 산출물이다.

- A4 세로, 상하22mm·좌우20mm, 본문2단·단간10mm, Pretendard10pt/1.5. 첫 쪽은 전체 폭 제목·저자·발표일·행사 정보 바로 아래 본문을 시작한다. 독립 표지를 추가하지 않는다.
- 사진·스크린샷은 한 단 폭과 원본 비율을 유지한다. 표만 실제 측정 결과에 따라 전체 폭으로 넓힌다. 절별 강제 페이지 나눔은 꺼 둔다. 원문 누락, 무조건 축소, 이미지를 잘라 넣는 방식은 금지한다.
- 등록자가 content/print.json의 저자와 짧은 제목을 실제 원문에 대조한다. 날짜·행사는 작품 메타데이터에서 가져온다. 머리말·꼬리말에는 짧은 제목·저자·날짜·쪽 번호를 배치한다. 소속과 설명을 추측해 만들지 않는다.
- scripts/hanmark의 MIT HanMark2.7.0 순수 조판 모듈과 첫 쪽 여유 공간 확장을 사용한다. provenance.json에 원본 revision/파일 해시를 고정한다. Obsidian 설정·저장 API는 가져오지 않는다. 본문 DOM 어댑터는 인라인 목록을 블록으로 감싸지만 글자를 바꾸지 않는다.
- 생성 환경은 package-lock의 Playwright/Chromium·esbuild와 PyMuPDF1.27.2.3이다. `npx playwright install chromium` 후 `npm run print:generate`로 네 원고를 생성한다. `PRINT_PYTHON`으로 검증용 Python 실행 파일을 지정할 수 있다. Vercel은 PDF를 생성하지 않고 검증된 정적 파일을 배포한다.
- content/print-manifest.json에 입력 digest·엔진·Chromium 버전·PDF 해시·쪽수·검사 결과를 기록한다. 원문·이미지·메타데이터·폰트·조판 코드가 바뀌면 재생성해야 빌드가 통과한다. URL은 PDF 내용 해시를 사용한다. 이미 운영에 게시한 PDF URL은 보존한다.
- PDF는 본문 전체 순서, 반복 표 머리행을 제외한 문자 보존, 원본 이미지 수, 페이지 경계, 한글 추출, 폰트 포함, A4와 실제 PDF 페이지 수를 검사한다. 모든 페이지 렌더를 시각 점검하고 검토 영수증을 남긴다. 본문·표가 읽기 어려우면 자동 통과 여부와 무관하게 수정한다.
- 원고·프리셋 개정은 기존 읽기 전체에 소급 적용한다. PDF 버튼 열기·다운로드, 모바일·데스크톱, 기존 발표/PDF/포스터와의 구분을 검토한다. 미검증·누락 PDF는 게시하지 않는다. 초안은 생성하지 않는다. 파생 PDF는 검색 중복 방지를 위해 noindex로 제공한다.

원본 그림/스크린샷에 담긴 글자는 이미지 그대로 보존한다. PDF는 인쇄·열람용이며 물리 프린터 실물 교정이나 PDF/UA 인증을 자동 검사 통과로 주장하지 않는다.

넓은 표는 앞선 제목·본문 뒤에 놓고, 남은 공간에는 다시 2단 본문을 이어 붙인다. 표 앞뒤의 밴드마다 왼쪽 단→오른쪽 단 순서를 검사한다. 긴 제목·URL·중첩 목록·긴 코드·65행 표·세로 이미지 스트레스 원고는 `npm run print:test`로 검사하며 공개 자료에 섞지 않는다.

브라우저 자체의 확장 UI가 자동조작을 차단하면 열기 결과를 성공으로 꾸미지 않는다. 실제 PDF 다운로드·파일 해시 일치, 해당 URL의 HTTP 200과 동일 바이트, 전체 쪽 시각 검토가 모두 있어야 제한 사유를 명시한 `browser-blocked` 검토를 허용한다. 뷰어 내부 조작은 미검증으로 기록한다. 일반적인 링크·다운로드 오류에는 이 예외를 적용하지 않는다.
