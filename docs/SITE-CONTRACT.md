# 사이트 규약 3.2.0

프로젝트는 한 번 등록한다. 슬라이드·읽기·PDF·포스터·영상·실습 자료는 해당 프로젝트의 산출물이다. 포스터 갤러리는 별도 작품을 복제하지 않고 프로젝트를 가리킨다. 상단은 대표작·전체 자료·Motion·소개, 포스터와 영상은 전체 자료 아래에서 찾는다.

## 전체 원문 읽기

[읽기 계약 1.0.0](READER-CONTRACT.md)을 적용한다. 모든 발표의 원문 전체·이미지·목차·복사·저장·연결 지도와 생성 읽기 페이지의 소급 검수를 필수로 한다. 아래 포스터 규약의 고정 출력은 유지한다.

스크롤 중에도 목차와 밝음·어두움 전환을 같은 고정 도구줄에서 바로 사용할 수 있어야 한다. 테마를 바꾸려고 문서 맨 위로 돌아가게 만들지 않는다. 목차 패널을 열어도 테마를 바꿀 수 있어야 하며, 모든 테마 버튼의 상태·레이블·브라우저 저장값이 같아야 한다. 조작 영역은 최소44px, 테마 전환은 현재 읽기 위치를 유지한다. 모든 기존 읽기의 처음·중간·끝을375/768/1440px 양테마에서 실측해 readerNavigation 영수증으로 남기며, 누락·가림·겹침·동기화 실패는 배포를 차단한다.

## 등록 계약

공개 자료에는 제목, 요약, 날짜, 등록일, 유형, 주제, 공개 범위, 미리보기와 대체 텍스트를 작성한다. 발표·강의는 대상과 얻을 내용, 모션은 제작 의도와 실제 영상이 필요하다. 대표작은 선정 이유를 남긴다. 카드에는 실제로 있는 산출물만 최대 3개와 더 보기를 제공한다.

포스터는 content/resources.json에 id/kind:poster/workId/title/summary/body/preview/previewAlt/currentVersion/versions를 등록한다. versions에는 id/html 및 필요한 pdf/image, engineVersion/viewerVersion/packageSha256/files(URL→SHA256)를 적는다. 호환 뷰어는 content/site-policy.json의 명시 목록을 따른다. 단일 포스터 rc6와 순환 포스터 rc1/rc2 계약을 구분한다. 미리보기는 로컬 공개 이미지다. HTML/PDF는 검토된 공개 주소 또는 저장소 자산을 사용한다. 외부 주소는 HTTP와 해시를 별도 확인해 영수증에 기록한다. 링크 전용은 목록·검색·사이트맵 제외, 초안 자산은 public에 놓지 않는다.

포스터 본문 검색은 프로젝트 1건으로 합쳐지고 해당 포스터 위치로 이동한다. 독립 포스터도 kind:poster 프로젝트를 만든다. 다른 사람의 포스터는 권한·소유를 확인하기 전 개인 작품으로 등록하지 않는다.

## 포스터 화면

기본 화면에는 44px 조작 영역의 ⋯만 표시한다. 도구 전용 윗줄을 확보하지 않는다. 열린 메뉴에서 테마·PDF·확대·종이·인쇄·도움말을 제공한다. Esc/바깥 클릭으로 닫는다. 화면과 PDF의 역할을 구분하며 인쇄에는 도구를 넣지 않는다. 제목·본문과 버튼의 겹침, 안전 여백, 확대 후 리사이즈를 검사한다.

## 필수 배포 순서

1. 명시적 자료 등록과 파일별 SHA256 확인.
2. npm run content:check (읽기 전용), npm run build, npm run check, npm test.
3. 로컬 미리보기에서 모든 비초안 프로젝트 상세와 /, /archive/, /posters/를 375·768·1440px × 밝음·어두움 검사. 검색·빈 결과·URL 복원·키보드·포스터 통합 시험도 실행.
4. npx tsx scripts/release-gate.ts --digest로 산출한 해시와 실제 views를 validation/release-review.json에 기록. 기능 결과와 증거 위치를 적는다.
5. npm run release:verify. GitHub 푸시 후 Vercel 미리보기, 운영 배포와 기존 URL 확인.

검토 영수증은 사람이/AI가 실제 확인했다는 추적 기록이며 악의적인 관리자의 변조를 막는 보안 서명은 아니다. 자동 코드는 스키마·파일 해시·초안 노출·링크·색인·검토 버전·검토 누락을 차단한다. GitHub 저장소의 브랜치 보호 설정은 별도 원격 설정이다.

## 변경과 소급 적용

메뉴·표시 규칙·필수 필드·뷰어를 바꿀 때 정책 버전, 구현, 운영 문서를 같은 변경으로 갱신한다. 전체 works/resources를 이관한 뒤 전수 검사를 실행한다. 검토 digest는 코드·콘텐츠·공개 파일·선언된 원문·규약을 포함한다. 불합격을 피해 예외를 자동 추가하지 않는다. 예외는 구체적인 자료 ID·규칙·근거를 기록하고 사용자 범위와 대조한다.

복구는 직전 정상 배포로 전환한 뒤 같은 Git 변경을 되돌려 다음 빌드도 일치시킨다. 과거 포스터 PDF/URL을 덮어쓰는 작업은 별도 본문 변경 요청이 있을 때만 한다.

## PS09 · 화면과 종이의 병렬 편집
HTML은 완결 포스터 여러 장을 기본 4초 간격으로 순환한다. 기본 선택은 '라이트·다크 교차'이며 장 번호에 따라 색을 전환한다. authored는 별도 선택이다. 새 저장 키의 명시적 light/dark 선호는 보존하되, 기존 저장 값이 새 기본값을 가로막지 않도록 한다.

모바일 세로 화면은 모든 장의 논리폭·높이·배율·좌우·상단을 공유하면서 본문 가로 점유율 90% 이상을 우선 확인한다. 후보 폭별 실제 표시폭을 우선하고 동률이면 배율을 선택한다. 짧은 가로 화면은 전체 보기와 크게 읽기를 유지한다.

A2는 기본 한 장이다. HTML 장수를 PDF 장수로 복제하지 않는다. 같은 사실 원장에서 별도 2열·다열 편집으로 전체 원고를 한 장에 완결한다. 제목·행사 정보·모든 연사와 주제·일정·조건·출처를 동시에 읽을 수 있는 전통적 포스터 위계를 설계한다. print.rows를 직접 설계한다. print.pages는 사용자가 종이 복수 장을 별도로 명시한 경우에만 allowMultiplePages=true와 multiPageReason으로 허용한다. HTML이 여러 장이라는 이유는 승인이 아니다.

종이 본문 18pt 이상에서 열 너비·중복 정보·제목과 도표 배치를 조정한다. 공간이 부족하면 다시 편집하고 오류를 보고한다. 무제한 축소나 종이 페이지 추가로 해결하지 않는다. academic-one-sheet는 별도 2열 편집·큰 제목·정렬된 공동기관 로고·하단 행사 QR을 제공한다.

print.iccProfile은 명시적 CMYK 출력 ICC 경로다. sRGB 입력색을 LittleCMS 상대 색도계로 변환하고 PDF OutputIntent에 동일 ICC를 내장한다. 작은 검정 본문과 QR은 K100으로 출력한다. 공개 spec에는 경로 대신 프로파일 이름·해시·출력 조건을 남긴다. SVG와 QR의 기본색도 Canvas 경계에서 변환하고 RGB 연산자 0을 검사한다. 불필요한 기본 폰트를 제거하고 남은 모든 폰트의 내장을 검사한다.

인쇄소 지정 프로파일이 없으면 선택한 출력 조건의 준비본(prepared-cmyk)으로 구분한다. 특정 코팅지 ICC는 모든 출력기의 보편 설정이 아니다. 인쇄소·용지 확인 전 press-approved 또는 PDF/X 인증을 주장하지 않는다. 프로파일이 없으면 RGB 교정본(needs-print-profile)이다. 치수·bleed·폰트·원고·색 연산자·프로파일 해시를 preflight에 남긴다. PDF 1장·HTML 2장 회귀 시험을 필수로 한다.

## PS10 · 모바일 HTML 공유 미리보기
순환 포스터에도 공유 이미지를 독립 산출한다. 1200×600 RGB PNG와 내용 해시 파일명, 절대 HTTPS canonical/og:url/og:image·제목·설명·이미지 형식/크기/대체텍스트를 초기 head에 넣는다. A2 전체 인쇄 미리보기를 OG로 재사용하지 않는다.
공개 poster.html은 폰트·PDF를 별도 파일로 제공하고, poster-offline.html은 같은 본문과 PDF를 내장한다. 공개 파일은 share-manifest.json의 명시된 파일·SHA256만 게시한다. 폴더 재귀 복사 금지. 프로젝트 자체 예산은 HTML256KiB/head64KiB/이미지1MiB이며 카카오 공식 크기 제한으로 주장하지 않는다.
생성→시각 검수→게시→공개 HTML·이미지·폰트 HTTP200/형식/크기/해시 및 canonical 확인을 필수로 한다. 일반 UA와 카카오 UA 응답을 비교하되 실제 카카오 수집 성공과 구분한다. 카카오 metadata debugger 로그인/캐시 확인 또는 실기기 카드 확인 전에는 kakao-preview-verified로 표시하지 않는다. 이미지 변경 시 URL도 해시로 바뀐다. 저장된 미리보기 갱신은 공식 도구 https://developers.kakao.com/tool/debugger/sharing 를 사용하며 메시지는 사용자 요청 없이 발송하지 않는다.
공유 공개 HTML의 수정이 화면 4초·교차 테마·공통 기하·넓은 모바일 폭·독립 A2 한 장을 바꾸면 안 된다. 종이 엔진은 PS09핀을 유지한다. 기존 legacy 출력은 승인 버전을 유지한다.
